# GAMBIT GRID

> 규칙을 짜서 AI를 싸우게 하는 격자 오토배틀러.
> 플레이어는 유닛을 조종하지 않는다. **유닛의 판단 기준을 조종한다.**

기획서는 [DESIGN.md](DESIGN.md), 에셋 출처는 [CREDITS.md](CREDITS.md).

---

## 실행

```powershell
.\run.ps1            # 데스크탑 데모
.\run.ps1 test       # 헤드리스 검증 122개
.\run.ps1 mc         # 몬테카를로 밸런스 시뮬레이션 (약 2분)
.\run.ps1 explore    # 편성 탐색 표
.\run.ps1 export     # 웹 빌드 -> ..\build\web
.\run.ps1 serve      # 웹 빌드를 로컬 서버로 (Ctrl+C 로 종료)
.\run.ps1 web        # export + serve
.\run.ps1 import     # class_name 재등록 (파일 추가 후)
```

Godot **4.7.1** 사용. 경로는 `run.ps1` 상단 `$dir` 에 하드코딩되어 있다.

### 개발용 환경변수

무인 캡처·백업 영상 촬영용. 게임 규칙과는 무관하다.

| 변수 | 효과 |
|---|---|
| `GG_SCREEN=loadout \| loadout_full \| battle` | 예산을 자동으로 털어 해당 화면부터 시작 |
| `GG_STAGE=2` | 시작 스테이지 |
| `GG_AUTOSTART=1` | 전투 화면에서 즉시 재생 |
| `GG_SPEED=4` | 배속 |

## 게임 흐름

```
1단계 덱 구성  →  2단계 편성과 배치  →  3단계 전투
        ←  덱부터 다시      ←  편성 고치기
                                  └ 승리 시 → 다음 스테이지
```

1. **덱 구성** — 예산 24 안에서 규칙 카드를 산다. 상점 5칸, 리롤(-1), 카드별 영구 추방.
2. **편성과 배치** — 5종 중 3명을 골라 아군 진영 6칸 중 3칸에 세우고, 산 카드를 슬롯에 꽂는다.
3. **전투** — 개입 불가. 매 틱 유닛이 자기 규칙을 위에서부터 읽어 실행한다.

### 핵심 설계 결정

**1. 전투는 난수를 한 번도 쓰지 않는다.**
행동 순서는 유닛 인덱스 고정, 모든 동점은 인덱스와 방향 순서로 끊고, HP 비율 비교는
정수 연산만 쓴다. 같은 편성·같은 카드 = 항상 같은 결과. 영상을 몇 번이든 다시 찍을 수
있고 디버깅도 쉽다. 상점 리롤에만 난수가 있고 그 시드도 스테이지마다 고정이다.

**2. 규칙은 폴스루한다.**
조건이 참이어도 그 행동이 실제로 불가능하면(대상이 없거나 사거리 밖) 다음 슬롯으로
내려간다. 이게 없으면 `돌격 → 교전` 같은 조합이 성립하지 않는다 — 돌격의 조건이
`항상` 이라 슬롯 1에서 무조건 이기고 교전이 영영 실행되지 않기 때문이다.

**3. 직업 기본기는 슬롯 3칸 *아래*에 붙는다.**
위에 두면 조건이 헐거운 기본기가 매번 먼저 터져서 비싸게 산 카드가 무의미해진다.
아래에 두면 유닛은 빈손이어도 제 몫을 하고, 카드는 기본 행동을 덮어쓰는 상위 규칙이
된다. 기본기는 전부 대응 유료 카드보다 문턱이 빡빡하다(예: 악사 기본기 25% / 구호 50%).

**4. `Battle` 은 뷰를 모른다.**
`battle_event` 시그널만 뱉고, 뷰는 그걸 구독해 Tween 을 재생할 뿐이다. 연출을 아무리
바꿔도 전투 결과는 변하지 않는다.

## 검증

```powershell
.\run.ps1 test
```

122개 검사. 결정론(3회 실행 스냅샷 완전 일치), 승/패/타임아웃 세 종료 분기,
폴스루, 기본기 폴백, 반격 대상 되짚기, 상점 재현성, 소프트락 방지 등.

밸런스는 몬테카를로로 본다 — 전투가 결정론적이므로 표본을 뿌리는 대상은 전투가 아니라
**설정 공간**(편성 × 자리 × 예산 내 카드 조합)이다. 시드 고정이라 출력도 재현 가능하다.

> **주의:** 몬테카를로는 카드를 유닛에 무작위로 꽂는다. 그래서 `거리 유지` 처럼
> 팀 전체가 한 방향으로 통일돼야 작동하는 빌드 정의형 카드는 항상 최악으로 나온다.
> 카드가 나쁜 게 아니라 시뮬레이터가 못 쓰는 것이다. 이 수치만 보고 튜닝하면 헛짚는다.

## 웹 배포

`export_presets.cfg` 의 **`thread_support=false`** 가 핵심이다.
Godot 웹 빌드는 원래 `SharedArrayBuffer` 를 요구하고 그건 서버가 `COOP`/`COEP` 헤더를
보내야 하는데, **GitHub Pages 는 그 헤더를 보낼 수 없다.**

스레드를 끄면 `index.html` 에 `GODOT_THREADS_ENABLED = false` 가 박히고,
`index.js` 의 SharedArrayBuffer / Cross-Origin Isolation 검사가 `if (supportsThreads)`
블록 안에 있으므로 애초에 실행되지 않는다. 헤더 없는 평문 서버에서 확인 완료.

`.\run.ps1 serve` 는 헤더를 아무것도 붙이지 않는 서버라 **Pages 와 같은 조건**이다.

첫 로딩은 wasm 39MB 라 10~20초 걸린다. 모바일 브라우저는 지원하지 않는다.
